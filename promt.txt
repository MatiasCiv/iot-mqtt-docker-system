Estoy desarrollando un sistema IoT modular para monitorización y control de cultivos, basado en arquitectura de microservicios y comunicación mediante MQTT, desplegado con Docker Compose.

✅ Estado actual del sistema:

El sistema está completamente operativo en entorno local (Windows + Docker) y consta de tres servicios principales:

---

🏗️ Arquitectura general

El sistema sigue una arquitectura desacoplada basada en eventos:

[Python BLE Service] → (MQTT) → [Backend .NET] → (SQLite)

Y ahora incluye interfaz web básica:

[Navegador] → (HTTP API .NET) → (SQLite)

---

🔧 Servicios implementados

1. ✅ Servicio de ingesta (Python - ble-service)

- Lenguaje: Python 3.11
- Contenedor Docker: ble-service
- Librerías: paho-mqtt
- Función:
  - Simulación de datos de sensores (temperatura y humedad)
  - Publicación cada 5 segundos
- Topic MQTT:
  "ble/readings"

Ejemplo de mensaje:
{
  "deviceId": "ESP32_SIM",
  "temperatura": 22.3,
  "humedad": 45.1
}

---

2. ✅ Broker MQTT (Mosquitto)

- Contenedor: mqtt
- Puerto expuesto: 1883
- Función:
  - Canal central de comunicación desacoplada
- Flujo:
  Python → publish
  Backend → subscribe

---

3. ✅ Backend (.NET 8 - Web API)

- Framework: ASP.NET Core (Minimal API)
- Librería MQTT: MQTTnet
- ORM: Entity Framework Core (SQLite)

Funciones:

✅ Recepción de datos MQTT
✅ Deserialización JSON → modelo Reading
✅ Persistencia en base de datos SQLite
✅ Exposición de API REST

---

📦 Base de datos

- Motor: SQLite
- Archivo: readings.db
- Ubicación: volumen Docker en carpeta local `/data`

Modelo:

Reading:
- Id (int)
- DeviceId (string)
- Temperatura (double)
- Humedad (double)
- Timestamp (DateTime)

Configuración clave:

Data Source=data/readings.db

Modo WAL activado:
PRAGMA journal_mode=WAL;

---

🔁 Flujo de datos completo

1. Python genera datos simulados
2. Publica en MQTT (ble/readings)
3. Backend recibe evento MQTT
4. Deserializa JSON → objeto Reading
5. Guarda en SQLite con SaveChangesAsync()
6. API REST permite consultar datos

---

🌐 API REST disponible

GET /readings
→ devuelve últimas 50 lecturas

GET /readings/{deviceId}
→ filtra por dispositivo

Ejemplo:
http://localhost:5000/readings

---

🐳 Docker / Orquestación

Se utiliza docker-compose con tres servicios:

- mqtt
- ble-service
- backend

Red interna Docker:
- backend conecta a mqtt por hostname "mqtt"

Volumen persistente:
- ./data:/app/data

Puerto expuesto:
- backend → 5000
